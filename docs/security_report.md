Отчёт по аудиту безопасности
Проект: Webinar Platform API (FastAPI)
Тип аудита: Code Review + Security Assessment
Дата: 15 мая 2026
Критические и высокие проблемы
1. Полное отсутствие аутентификации и авторизации
Риск: Критический (CVSS ~9.5)
Любой анонимный пользователь может:

Создавать комнаты
Писать в чат от имени любого пользователя (impersonation)
Отвечать на опросы
Удалять комнаты

Рекомендация:

Внедрить JWT или OAuth2 (FastAPI Users / Authlib)
Добавить зависимости Depends(get_current_user)
Разделить роли: speaker, moderator, participant


2. XSS уязвимость в чате
Риск: Высокий
Сообщения из чата сохраняются и возвращаются как есть без экранирования. Если фронтенд отображает их через innerHTML или dangerouslySetInnerHTML — возможна кража cookies, session hijacking и т.д.
Рекомендация:

В ChatMessageCreate добавить санитизацию:Pythonfrom html import escape
message = escape(body.message)
Или использовать библиотеку bleach / markdown с whitelist'ом.


3. Отсутствие ограничения количества голосований в опросах
Риск: Средний/Высокий
Один пользователь может проголосовать в одном опросе неограниченное количество раз. Это ломает всю статистику и смысл опросов.
Рекомендация:

Добавить проверку "один голос от username на poll_id":Pythonexisting = any(a for a in poll_answers.values()

if existing:
    raise HTTPException(400, "Already voted")


4. Отсутствие Rate Limiting
Риск: Средний (DoS + Spam)
Нет защиты от:

Флуда сообщениями в чат
Массового создания комнат
Массового голосования

Рекомендация:

Подключить slowapi или fastapi-limiter:Pythonfrom slowapi import Limiter
limiter = Limiter(key_func=get_remote_address)
@app.post("/rooms/{room_id}/chat", dependencies=[Depends(limiter.limit("10/minute"))])


5. Отсутствие валидации и санитизации username
Риск: Средний
Username принимается любой строкой длиной 1-100 символов. Можно использовать спецсимволы, эмодзи, очень длинные имена, пробелы и т.д.
Рекомендация:
Улучшить модель:
Pythonusername: str = Field(..., min_length=2, max_length=50, pattern="^[a-zA-Z0-9_.-]+$")

Дополнительные проблемы
6. In-memory хранилище + нет защиты от race conditions
При одновременных запросах (например, несколько голосований) возможны гонки. После перехода на БД проблема частично решится, но нужны транзакции.
7. Отсутствие CORS настройки
Если фронтенд будет на другом домене — по умолчанию FastAPI разрешает все. Нужно явно настроить CORSMiddleware.
8. Слабая валидация статусов комнат
Статус можно установить в любое значение через RoomUpdate, если не вызвать validate_status() (а в PUT она вызывается, но легко обойти).
9. Нет защиты чувствительных операций
Любой может удалить комнату (DELETE /rooms/{id}) без подтверждения и прав владельца.
